# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

A Streamlit app for Monster Hunter Wilds with two features: an armor set optimizer ("Armor Set Maker") and a RAG-powered Q&A assistant ("The Guild Oracle"), both built on data scraped from game8.co.

## Commands

```bash
# Install dependencies (Python 3.10)
pip install -r requirements.txt

# Run the app locally
streamlit run app.py
```

There are no automated tests, linter configs, or CI workflows in this repo currently — don't assume `pytest`/`flake8`/`ruff` commands exist.

### Secrets

The RAG assistant page (`pages/2_mh_wilds_assistant.py`) requires an OpenAI API key at runtime via Streamlit secrets. Create `.streamlit/secrets.toml` (gitignored) with:
```
OPENAI_API_KEY = "your-openai-api-key"
```

## Architecture

This is a Streamlit multi-page app: `app.py` is the home page, and each file in `pages/` is a separate page/feature, numbered for ordering in the sidebar.

### Data pipeline (scrape → clean → csv)

`src/scraper.py` (`Scraper`) and `src/cleaner.py` (`Cleaner`) form a two-stage pipeline that pulls raw HTML tables from hardcoded game8.co URLs and writes cleaned CSVs to `src/data/` (`armors.csv`, `decorations.csv`, `skills.csv`, `talismans.csv`). Each `Scraper.*_scraping()` method returns a raw DataFrame; the corresponding `Cleaner.*_cleaning()` method parses game8's encoded strings (e.g. skill names fused with Roman-numeral-like level suffixes, `①②③` slot-size glyphs) into normalized columns and overwrites the CSV in place.

This pipeline is invoked live from `pages/1_mh_wilds_set_maker.py` on page load, gated by `st.session_state['try_to_update']`: it attempts a re-scrape/re-clean, and on failure falls back to the CSVs already committed in `src/data/`. When editing scraping/cleaning logic, be aware the site's table structure (column headers, glyph encodings) is what's being parsed — there's no schema to check against other than the live page.

### Armor set optimization (`src/set_maker.py`, `src/armor_set.py`)

`SetMaker` implements a brute-force search over armor combinations:
1. `filter_relevant_armors_and_talismans` narrows armors/talismans down to ones granting a requested skill (plus the best-per-skill talisman).
2. `make_armor_sets` performs a depth-first recursion (`_armor_set_recursion`) across the 5 armor slots (head/chest/arm/waist/leg) × filtered talismans, building every combination as an `ArmorSet` object, then flattens all of them into one big DataFrame via `pd.json_normalize`.
3. `filter_valid_armor_sets` drops combinations that exceed a skill's max level (from `skills.csv`).
4. `add_defense_by_skills_to_armor_sets` applies defense-boosting skill effects (Defense Boost, elemental resistances) via a hardcoded bonus table.
5. `get_best_set` sorts by requested skill levels first, then by defense or decoration score (user's choice), and returns the single best row.

`ArmorSet` (`src/armor_set.py`) is the accumulator object used during recursion — it tracks equipped pieces, summed defense, a `skills` dict, and decoration slot counts per size.

Because this is a full combinatorial search over filtered armors, the candidate pool size after filtering directly drives runtime — keep that in mind when changing the filtering step.

### RAG assistant (`src/model.py`)

`Model` implements a simple RAG pipeline: `prepare_csv()` loads every CSV in `src/data/` and turns each row into a LangChain `Document` (cell values prefixed with column names for context), `create_database()` embeds them into an in-memory FAISS index via OpenAI embeddings, and `rag()` does similarity search + a single hardcoded prompt template against `gpt-4.1-mini`. The FAISS index is rebuilt on every page load (`pages/2_mh_wilds_assistant.py` calls `prepare_csv`/`create_database` at module scope); only the `Model` instance itself is cached via `@st.cache_resource`.

### Data files (`src/data/*.csv`)

These CSVs are both checked into the repo (used as fallback data) and regenerated by the scrape/clean pipeline. Column naming conventions to know when touching this data: armor/decoration skill columns follow `Skill_{n}_name` / `Skill_{n}_lvl` pairs; armor decoration slots are `Decoration_slot_{n}_size`; the set-maker's flattened output DataFrame prefixes skill columns as `skills_{SkillName}`.
